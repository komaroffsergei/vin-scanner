# Решения и открытые проверки

## Зафиксированные решения

| ID | Решение | Причина и следствие |
|---|---|---|
| D01 | Мок только в браузере | Прямой ответ пользователя. Нет HTTP mock API, localhost-сервера или обращения к тестовому BFF. |
| D02 | Ровно две вкладки, один активный владелец камеры | Мок/Paddle/Tesseract используют baseline camera, vin-scanner — свой штатный компонент. Перед передачей владения прежний поток прекращается. |
| D03 | Обычный JavaScript, Web Workers, WASM | Сохраняет переносимость исходного HTML; Node нужен только разработчику при будущей сборке. |
| D04 | Общий минимальный контракт OCR с тремя реализациями | Абстракция оправдана тремя реальными движками; универсальная plugin-система не нужна. |
| D05 | WASM CPU, один поток, один активный движок | Не требует SharedArrayBuffer/COOP/COEP как базового условия и ограничивает одновременную нагрузку. WebGPU не является скрытым fallback или требованием. |
| D06 | Форк работает полностью, без ограничения алгоритма | Прямое уточнение пользователя: сохранить голосование, исправления и штатные возможности. Strict normalization относится только к Paddle/Tesseract. |
| D07 | Подтверждение зависит от движка | Paddle/Tesseract — два свежих кадра; форк — собственные Tier A/B/C и native fallback без внешнего порога. Frozen источник отмечен, решение форка не переписывается. |
| D08 | Live-форк через оригинальный компонент; frozen через оригинальный worker | Сохраняются camera UI, manual burst, torch и весь inference/consensus. Тест снимка — отдельная взаимоисключающая сессия native worker, не core-only профиль. |
| D09 | Стоп уничтожает runtime, а не только скрывает превью | Так проще гарантировать завершение фонового вычисления и исключить поздние записи. Следующий запуск может инициализироваться заново. |
| D10 | Отчёт без VIN/OCR-текста/кадров | Сохраняются измерения и результаты проверок; экспорт не переносит исходные данные пользователя. |
| D11 | Один итоговый HTML — рабочее предположение | Пользователь назвал HTML как цель; отдельный ответ о допустимости внешних ресурсов не получен. До изменения этого предположения проектируется embedded-сборка, техническая осуществимость проверяется первой. |
| D12 | SDD — документы, контракты, трассировка и проверяемые этапы | `codex-workspace` не дал готового SDD-шаблона; Sepia — редактор прозы. Ни установка Spec Kit, ни генерация им файлов не заявляются. |

## Альтернативы, рассмотренные при проектировании

1. **Один встроенный HTML (целевая гипотеза):** удобно передать на телефон, нет runtime HTTP; сложнее упаковать worker/WASM/модели, выше размер и расход памяти. Требует проверки загрузчиков библиотек под `file:` и `blob:`.
2. **HTML + локальные ресурсы:** проще сборка и аудит ресурсов, но браузеры могут блокировать загрузку соседних файлов при `file:`. Само наличие файлов рядом не решает CORS/opaque origin. Без согласования не принимается за замену.
3. **HTTPS-страница с ресурсами:** удобнее камера и загрузчики, но появляется хостинг и сетевые запросы за ресурсами. Не соответствует принятому автономному профилю; отдельный возможный будущий вариант, не часть этой реализации.

## Условия, которые ещё предстоит доказать

| Вопрос | Как проверять | Последствие неуспеха |
|---|---|---|
| Все три библиотеки загружают embedded worker/WASM в целевом мобильном браузере? | T01: минимальный harness каждого движка, холодный offline-запуск, DevTools | Движок не объявляется готовым; фиксируется причина и пересматривается упаковка, без CDN fallback |
| Насколько велик итоговый HTML и каков пик памяти? | Фактический asset manifest, размер файла, доступные browser metrics, реальные слабые телефоны | Не декодировать невыбранные ресурсы; при нехватке памяти явно ограничить поддержку, не выдумывать лимит |
| Работает ли открытие `file:` именно в браузере телефона? | Реальные Android/iOS, записать приложение открытия, протокол и secure context | «Заблокировано средой», а не «телефон без камеры» |
| Какие именно Paddle-модели и eng traineddata войдут в сборку? | Зафиксировать asset URL/version/SHA-256/license на T02 | Пустой manifest не проходит сборочный этап |
| Является ли цель строго одним HTML обязательной? | Уточнение пользователя, если он решит изменить упаковку | Текущий план сохраняет один HTML; предположение остаётся видимым |
| Достаточно ли качество OCR? | Набор эталонных VIN-фрагментов + реальные условия; результаты отдельно по движкам | Не обещать production-точность; выбор движка только по измерениям |

## Лицензии

У форка заявлена AGPL-3.0-only, а NOTICE требует сохранять авторские уведомления и атрибуцию. PaddleOCR и Tesseract.js заявляют Apache-2.0, ONNX Runtime — MIT. В спецификации это характеристики исходников, не разрешение перелицензировать форк или его веса. При будущей сборке сохраняются LICENSE/NOTICE и происхождение каждого ресурса. Публикация и коммерческая интеграция сейчас не выполняются.

Первоначальное предложение отключить исправления/Tier C отклонено пользователем. Актуальные D06–D08 требуют полного поведения форка. Защита отмены, offline resource loading и RU локаль — интеграционные изменения; они не меняют decoder, веса, пороги, голосование, guide strips и native результат.
