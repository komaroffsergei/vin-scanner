# Передача в реализацию

Этот архив не устанавливает приложение и не реализует вкладки. В `baseline` находится прежняя диагностика. Новых npm scripts или запускаемого OCR-приложения пока нет.

## Исходники

Рядом с распакованным пакетом в рабочей директории уже клонированы `codex-workspace` и пользовательский `vin-scanner`. Точные пути, remote и SHA записаны в `context/provenance.json`. Воспроизведение на другой машине начинается с checkout этих SHA; приватный workspace требует доступа пользователя, для изучения публичного форка он не обязателен.

Не запускать workspace bootstrap/sync как часть стенда и не устанавливать shared plugin в глобальную среду. Для разработки OCR достаточно форка и правил его checkout. Перед изменениями прочитать применимые AGENTS.md.

## Порядок работы разработчика

1. Проверить D01 (только memory mock), D06–D08 (полноценный форк), D11 (single HTML как пока не подтверждённое отдельно предположение).
2. Прочитать `spec.md`, затем `research.md`; не считать заявления upstream о браузерах собственными измерениями.
3. Выполнить T01 с настоящими библиотеками. Не строить полный UI до доказательства автономных loader/worker/WASM.
4. На T02 зафиксировать версии и ресурсы; использовать lockfile/manifest вместо latest/CDN.
5. Пройти T03–T13 с сопоставлением FR/AC/TC. Каждое изменение контракта сначала отразить в документах и схемах.
6. Выдать отдельный build output `vin-scanner-diagnostics.html`, проверенный offline, и список фактически проверенных телефонов. Не перезаписывать пользовательский оригинал неявно.

Будущие команды установки/сборки должны появиться в README реализованного стенда после выбора инструментария T01–T02. Этот пакет не выдаёт выдуманный `npm run diagnostics` за уже существующую команду.

## Как пользователь будет проверять готовый HTML

1. Открыть файл в браузере телефона; если открылся просмотрщик без JS — увидеть статический fallback и записать среду.
2. На «Браузерный мок» открыть камеру, снять контрольный фрагмент и запустить основной/ошибочные сценарии. Методы/адреса только отображаются, реальной отправки нет.
3. На «На устройстве» выбрать Paddle/Tesseract/vin-scanner, нажать Start. Дождаться инициализации и разрешить камеру.
4. Для форка пользоваться штатным overlay/shutter/torch/retry; результат принять по native verdict. Для остальных — общий ROI и подтверждение.
5. Для сравнения зафиксировать один кадр, остановить камеру и последовательно прогнать движки. Сравнить с локальным эталоном; не смешивать frozen и live результаты.
6. Проверить Stop, поворот, фон, экранную блокировку и исчезновение индикатора камеры. Не ожидать автоматического возобновления.
7. Скачать/скопировать safe JSON; убедиться, что в нём нет VIN и фотографий.

HTTP-сервер, backend login, реальный BFF и доступ к облачному OCR для этой процедуры не нужны. На подготовке спецификации описанные runtime-действия не выполнялись.
